# Архітектура

Кожен config entry керує однією вибраною сутністю `climate`. `model.py` обчислює температурну потребу з гістерезисом, `strategy.py` — енергетичне рішення, `window.py` — середній баланс, `manual.py` — ручний пріоритет. Ці модулі не викликають API пристроїв.

`coordinator.py` читає джерела на подіях стану й кожні 30 секунд, синхронізує цикл із реальним кондиціонером, публікує діагностику та зберігає стан через HA Store. Команди виконуються асинхронно лише в режимі control. Context кожної команди й обмежене 30 секундами зіставлення очікуваних змін дозволяють відрізняти власні зміни від зовнішніх. Одночасно виконується одна команда; повтори однакової команди обмежені 30 секундами. Очікування сервісу обмежене 10 секундами. Після кожної команди координатор перевіряє актуальні умови й таймери, щоб одразу виконати потрібну зупинку. Завдання створюється через config entry з eager_start=False і скасовується при unload. Перехід у спостереження/вимкнення або unload скасовує незавершене завдання.

`select.py` створює єдиний перемикач режимів: disabled, observation, control, temporary_block. Тимчасове блокування встановлюється після зовнішньої ручної зміни або вибором у select; режим повернення та місцева дата блокування зберігаються разом у config entry options. Після місцевої півночі відновлюється попередній режим. Вибір іншого режиму скасовує блокування й автоматичне повернення. Стара окрема ручна пауза мігрує в temporary_block. Вибір зберігається у config entry options і застосовується відразу. Legacy enabled перетворюється на observation/disabled; автоматичне ввімкнення повного управління при оновленні відсутнє.

`sensor.py` та `binary_sensor.py` показують рішення й реальний стан. `config_flow.py` розділяє налаштування на джерела, комфорт, енергетику й розширені параметри; редагування розділу зберігає режим та інші параметри. Діагностика не експортує ідентифікаторів вибраних сутностей.

Правила: [стратегія](strategy.md). Локальні тести використовують чисте ядро й адаптер із моделями API; tests/ha перевіряють завантаження платформ і flows у HA.

`climate_control.py` перевіряє підтримку цілі, діапазон і крок пристрою та зіставляє очікувані відповіді. Енергетичний дозвіл і його причина не залежать від ручної паузи, розкладу, температурних даних чи вимкненого режиму. Помилки команд публікуються як код помилки без тексту винятку, що може містити ідентифікатори сутностей.

Manifest класифікує контролер як service: кожен запис забезпечує одну службу керування кондиціонером і відображається серед інтеграцій. DeviceInfo.configuration_url веде на внутрішню сторінку інтеграції з виділеним config entry, де шестерня відкриває Options Flow. Зміна типу не змінює domain, entry ID чи унікальні ідентифікатори сутностей.
