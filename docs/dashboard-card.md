# Картка управління та аналізу

[Готова YAML-картка](lovelace-card.yaml). [Та сама структура у JSON](lovelace-card.json).

Картка використовує стандартні tile, entities, conditional, markdown та history-graph Home Assistant. Додаткові картки з HACS не потрібні.

## Як додати

1. Відкрийте вашу панель → Редагувати → Додати картку → Вручну / Manual.
2. Скопіюйте весь вміст lovelace-card.yaml. Це одна vertical-stack картка, не конфігурація всієї панелі.
3. Замініть кожен умовний entity_id зі списку нижче фактичним entity_id потрібного запису інтеграції. Імена можуть відрізнятися залежно від мови HA та ваших перейменувань; заміна лише префікса scm_ може бути недостатньою.
4. Збережіть картку. Історія почне відображатися в міру накопичення даних у Recorder.

Сутності можна знайти на сторінці пристрою або через Інструменти розробника → Шаблони:

```jinja
{% for entity in integration_entities('solar_climate_manager') | sort %}
{{ entity }} — {{ state_attr(entity, 'friendly_name') }}
{% endfor %}
```

Для кількох кондиціонерів беріть усі сутності з одного запису.

## Що показує картка

Вибір режиму перемикає одну сутність select: все вимкнено, лише спостереження, повне управління. Ціль контролера, температура датчика кондиціонера, різниця датчиків, розрахована й фактично встановлена цілі показані через атрибути датчика рішення стратегії. Додаткових ID для цих рядків не потрібно. Бажана кімнатна ціль зберігається окремо від компенсованої цілі кондиціонера; її зміна, гістерезис, мінімальний SOC і джерела доступні через кнопку налаштувань і шестерню біля потрібного запису інтеграції.

Енергетичний дозвіл і дозвіл автоматичних команд показані окремо. Доступна мережа дозволяє енергетичну роботу навіть за низького SOC, коли вистачає ліміту імпорту та немає суттєвого розряду батареї. За достатнього SOC короткі піки розряду допускаються. Ліміт (0 — без обмежень), запас бюджету та ознака заданого ліміту показані через атрибути наявного датчика енергетичного дозволу; нових ID для картки не потрібно. Ручна пауза, вимкнений режим, розклад або відсутня температурна потреба можуть залишати кондиціонер вимкненим навіть за енергетичного дозволу.

Помилка команди, ручна пауза та некоректні дані з’являються окремими блоками, коли проблема активна. У редакторі HA умовні блоки можуть відображатися незалежно від поточного стану.

Додатна потужність батареї означає розряд, від’ємна — заряд. Додатна потужність мережі означає імпорт, від’ємна — експорт. Налаштуйте напрямок знаків у джерелах інтеграції.

Температура, потужність і SOC мають окремі графіки, щоб не змішувати одиниці. Відсутність виміряної потужності кондиціонера за неналаштованого окремого датчика є нормальною: поряд показана розрахункова оцінка. Невикористовувані рядки можна видалити. Порожній таймер означає, що для поточного рішення немає відліку.

«Все вимкнено» припиняє автоматику й залишає фізичний кондиціонер у поточному стані. Картка не надсилає прямих ручних команд climate; режим повного управління використовує стратегію інтеграції.
