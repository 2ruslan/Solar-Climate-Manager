# Solar Climate Manager — 0.3.3

Інтеграція Home Assistant для керування реальним кондиціонером з урахуванням кімнатної температури, стану батареї та доступності мережі.

[![Відкрити Solar Climate Manager у HACS](https://my.home-assistant.io/badges/hacs_repository.svg)](https://my.home-assistant.io/redirect/hacs_repository/?owner=2ruslan&repository=Solar-Climate-Manager&category=integration)

## Встановлення

1. Додайте `https://github.com/2ruslan/Solar-Climate-Manager` у HACS як користувацький репозиторій типу Integration, завантажте інтеграцію та перезапустіть HA. Для ручного встановлення скопіюйте `custom_components/solar_climate_manager` у `/config/custom_components/solar_climate_manager`.
2. Через **Налаштування → Пристрої та служби → Додати інтеграцію** виберіть Solar Climate Manager.
3. Виберіть кондиціонер, датчик температури, обігрів або охолодження, ціль та гістерезис. Ціль задається у °C; покази °F та команди для системи з °F перетворюються.
4. Відкрийте **Налаштування → Пристрої та служби → Інтеграції → Solar Climate Manager** і натисніть **шестерню біля потрібного запису кондиціонера**. Задайте джерела даних та енергетичні обмеження. Для керування потрібні SOC, потужність батареї та наявність мережі. Під час відключення потрібні також потужність СЕС і споживання.
5. На сторінці пристрою виберіть **Режим роботи**.

## Один перемикач із трьома станами

| Стан | Поведінка |
|---|---|
| Все вимкнено | Автоматизація не розраховує потребу та не надсилає команд. |
| Лише спостереження | Показує дані й рішення стратегії без команд кондиціонеру. Типовий режим після встановлення. |
| Повне управління | Запускає кондиціонер у вибраному режимі з цільовою температурою та вимикає його за рішенням стратегії. |

Перехід у вимкнений режим або спостереження припиняє автоматичні команди й залишає кондиціонер у поточному стані. Це вимкнення автоматизації. Режим зберігається після перезапуску та редагування налаштувань. Старий перемикач спостереження прибирається; наявні записи переходять у спостереження або вимкнений режим згідно з попереднім налаштуванням.

Датчик «Кондиціонер увімкнено» показує стан реального `climate`. Рішення «Запуск» у спостереженні означає рекомендацію стратегії. Помилка сервісу не вважається успішним запуском; повторна спроба можлива після 30 секунд. Окремі сутності показують помилку команди й причину енергетичного дозволу. Очікування сервісу обмежено 10 секундами; після завершення команди рішення перевіряється знову, а захисна зупинка відправляється без очікування наступного таймера.

Енергетичний дозвіл незалежний від режиму автоматизації, ручної паузи, розкладу й температурної потреби. За доступної мережі СЕС і прогноз не потрібні. Мінімальний SOC, тривалий розряд батареї та недоступні обов’язкові енергетичні дані залишаються причинами блокування; їх показує «Причина енергетичного дозволу».

Температурний датчик може повідомляти лише зміни: останній коректний показ не має обмеження віку. Тривала незмінна температура не створює розривів графіка й не блокує керування. Якщо джерело переходить у unknown/unavailable, зникає або повертає некоректне значення, температура стає недоступною й автоматична робота блокується. Обмеження віку енергетичних вимірювань збережено.

Ціль перевіряється щодо діапазону й підтримки кондиціонера та округлюється до підтримуваного кроку.

Зміни режиму, цілі, вентилятора або інших керованих атрибутів поза інтеграцією ставлять автоматизацію на паузу до місцевої півночі. Власні команди розпізнаються за контекстом HA або точним збігом змінених полів із очікуваною відповіддю протягом 30 секунд. Явні користувацькі команди, зміни вентилятора й інші неочікувані зміни залишаються ручними.

## Де змінити параметри

**Налаштування → Пристрої та служби → Інтеграції → Solar Climate Manager → шестерня біля потрібного запису кондиціонера**. Це відкриває меню **Джерела даних → Комфорт → Енергетика → Розширені**. Шестерня загальних параметрів сутності змінює назву й відображення, а не параметри контролера.

На сторінці пристрою посилання **Відкрити вебсайт / налаштування пристрою** веде до сторінки цієї інтеграції з виділеним потрібним записом. Режим роботи змінюється окремим трипозиційним перемикачем на пристрої.

Починаючи з 0.3.2, інтеграція має тип service і доступна у вкладці Інтеграції. Після оновлення файлів перезапустіть HA та оновіть сторінку браузера. Видаляти й повторно додавати запис не потрібно: його ідентичність, джерела, параметри й режим збережено.

Для другого кондиціонера створіть окремий запис. Повторне додавання того самого `climate` блокується.

Правила й таймери: [стратегія](docs/strategy.md). Будова: [архітектура](docs/architecture.md).

## Перевірка

```sh
python -m unittest discover -s tests/unit -v
python -m compileall -q custom_components tests
ruff check .
```

Інтеграційні тести HA потребують Linux та відповідного Python:

```sh
python -m pip install pytest-homeassistant-custom-component
pytest -q tests/ha
```

Локальні тести перевіряють ядро та адаптер із моделями API. Роботу з фізичним кондиціонером потрібно перевірити у вашій інсталяції HA. Команди інвертору не надсилаються; централізований розподіл потужності між кондиціонерами та Quiet/fan-комфорт не реалізовані.
